# Listing Studio

中文商品调研与标题工作台。上传图片、类目和两套占位模板后，后台使用本机 Codex 非交互执行器运行 ai-listing 技能，复用已登录的 Amazon/Sif 浏览器。任务串行执行，结果持久化到 `data/jobs/`。

## 使用

通过交付的网址进入。模板使用 `{主体风格}`、`{画风背景}` 等标记占位，其余文字保持不变。默认标题一65–75字符，标题二115–125字符，可展开字符范围调整。历史任务支持查看原词来源、完整竞品标题、图片、联合报告，以及下载含相对图片引用的 ZIP。

需要登录时，通过页面按钮打开现有浏览器，完成后点击继续。仅修改标题时固定原商品类目和来源；换类目需新建调研。服务中断保留任务资料，重启后可继续。下载接口不公开执行日志或内部任务文件。

## 保存和选择模板

标题区的“保存模板”可将两条模板、字符范围与可选类目成组保存到服务器；下次选择组合即可自动填入。支持命名、更新、另存和删除，刷新或更换设备后仍可读取。同类目同名不会静默覆盖，同时编辑会检查版本。更换类目时清除从旧类目组合填入的内容；通用组合可跨类目。保存或删除组合不会修改历史任务。

库文件位于忽略的 data/jobs/templates.json，不写入源码。首次已将用户历史任务中的实际组合保存为“挂画 · 最近使用”，没有创建示例模板或额外商品属性。

## ZIP 批量调研

上传 ZIP 后先显示有效图片清单和跳过原因。填写本批类目、选择模板组并开始，图片按自然文件名顺序串行处理，各自保存两条标题、实际 Sif 原词和独立联合报告；历史页可打开批次查看整体和逐图状态。每批最多100张，ZIP最大100MB，单图最大15MB、有效图解压后合计最大300MB。支持JPG、PNG、WebP；不支持加密包、RAR和7z。混合类目的图片请分批上传。

提交时固定类目、两条模板和范围，之后修改模板库不会影响排队任务。登录受阻会暂停整个队列，完成登录后点击“已登录，继续队列”，先继续受阻图片；普通单项失败继续后续，可单独重试。资源不足会暂停整个队列。异常重启后，中断图片和原排队顺序保留，但不会自动重跑；检查服务器和浏览器后点击“检查后继续队列”再恢复。停止本批不会删除已有报告。上传并准备好的清单可在同设备刷新后恢复。

## 运行与检查

依赖：Node.js 22或更高版本、Python 3（标准库 zipfile）、ImageMagick `convert`、已认证的本机 `codex`，以及现有浏览器 `127.0.0.1:9223`。无 npm 第三方运行依赖。

```bash
npm test
npm run check
npm start
```

服务仅监听 `127.0.0.1:7350`，由现有 Nginx 的 `/listing-app/` 转发。随机私人访问路径保存在 `.runtime.json`，该文件及任务数据不进入 Git；不要把私人链接发给无关人员。

常驻服务配置见 `ops/listing-web.service`，部署后通过 `systemctl status listing-web`、`systemctl restart listing-web` 管理。重启不会删除已保存资料。

## 删除历史记录

历史任务每条记录右侧及详情页提供删除按钮；批次列表和批次详情支持删除整批历史。删除前会确认。运行、排队、等待登录或正在收尾的任务需要先停止；整批删除会先核实所有成员均可删除，再处理所选批次。

删除从网站的历史、统计、详情、图片、报告和下载入口中移除记录。原始任务目录和资料保留，使用持久的 `deletedAt` 标记隐藏，便于管理员处理误删；删除不等于清理磁盘。模板库和其他任务不受影响。批次内单条删除会同步调整剩余数量，最后一条删除后移除空批次；导入历史删除后重启也不会重新出现。

删除记录不会自动放开资源或登录暂停。相关暂停标记会保留到用户确认继续，但已删除任务不会再次执行。删除和继续任务按同一队列顺序处理，防止并发请求使已删除记录进入执行队列。

验证：76项自动测试、9组电脑和手机真实浏览器操作通过，并通过隔离服务重启验证。测试数据与生产历史分离。

## 每项结束后的浏览器页面回收

当前任务收尾、报告及图片校验保存后，工作台先关闭专用浏览器中的页面，只留一个空白页，再启动下一项。Cookie、登录状态、磁盘浏览器配置、报告和图片保留。任务部分完成、等待补充资料、失败或取消，也会在执行器退出后整理页面。

需要登录或验证码时保留原页面，队列继续保持登录屏障。浏览器页面整理失败不会把已有成果改成失败，而会暂停后续任务，并显示“重试页面整理”；恢复浏览器连接后点击重试再继续。失败屏障写入任务资料，服务重启后仍保留。

只修改当前工作台的任务收尾逻辑，不操作其他浏览器实例。首次部署这项后端改动需重新加载服务；排队任务与已保存资料保留。

## 2GB 服务器的资源保护

Listing 后端、它启动的执行器及图片处理进程、专用浏览器共同放入 `listing.slice`，共享物理内存硬上限 1GiB、交换空间上限 512MiB、一个 CPU 核心的配额和 512 个进程/线程的上限。内存超过 832MiB 后开始回收和节流。这是整个 Listing 的合计预算，不能分别给浏览器和后端各分配一份。

子进程达到内存上限时可能被终止，任务会报错或页面需要重新打开；不承诺当前机器能完成所有调研。服务使用 `OOMPolicy=continue`，让仍存活的后端有机会记录执行器失败，同时提高 Listing 进程的 OOM 优先级。整个服务若退出，五分钟内最多自动启动三次，防止反复重启。历史任务、报告和浏览器登录资料不受配置文件修改影响。

部署时先确认没有运行中的任务，再安装配置并重新启动两个服务：

```bash
install -m 0644 ops/listing.slice /etc/systemd/system/listing.slice
install -D -m 0644 ops/listing-web.service.d/20-resources.conf /etc/systemd/system/listing-web.service.d/20-resources.conf
install -D -m 0644 ops/listing-browser.service.d/20-resources.conf /etc/systemd/system/listing-browser.service.d/20-resources.conf
systemd-analyze verify /etc/systemd/system/listing.slice /etc/systemd/system/listing-web.service /etc/systemd/system/listing-browser.service
systemctl daemon-reload
systemctl stop listing-web.service
systemctl restart listing-browser.service
systemctl start listing-web.service
systemctl show listing.slice -p MemoryCurrent -p MemoryPeak -p MemoryHigh -p MemoryMax -p MemorySwapMax -p CPUQuotaPerSecUSec -p TasksMax
```

### 运行中的保护和请求限制

开始任务前核实共同资源上限及可用内存，预留至少192MiB工作台内存预算、256MiB服务器可用内存。执行中每两秒检查：工作台内存达到硬上限90%、服务器可用内存不足128MiB、多余标签页自动关闭失败、浏览器断连或出现新的工作台OOM事件，都会停止当前执行器并持久暂停队列。交换空间达到上限75%时，结合实际压力判断：只有同时出现持续内存阻塞（10秒some均值至少20%或full均值至少5%），或主机可用内存不足256MiB才暂停；历史冷页占用本身不会中止任务。接近交换硬上限时仍提前暂停，512MiB预算下保留32MiB余量。停止先发SIGTERM，三秒后强制清理同一任务的残余进程；45分钟超时也执行相同的停止流程。

资源检查故障时保守暂停；生产服务不在受限的 `listing.slice` 中时拒绝启动任务。资源暂停和异常中断必须经用户确认再继续；重启不能绕过。点击“检查后继续队列”会优先恢复被资源保护中止的图片，再处理原排队任务；从任务详情直接继续也会同步核实并解除资源屏障，已取消的任务保持取消。继续执行时读取上轮previous-progress.json及本商品已有竞品/Sif文件，补齐缺口。浏览器启动时只打开空白页，已有登录资料保留。清理时等待Chrome实际移除页面，最多等待三秒，避免关闭接口先响应造成误报。

任务正常结束、取消和超时后都会回收执行器进程组中残留的辅助进程。执行器启动失败或立即退出时处理stdin管道错误，避免错误退出整个后端。

专用浏览器最多保留2个业务标签页。任务执行器按阶段复用一个已加载的研究页面；后端每秒检查一次，运行中和空闲时都会优先关闭空白页、再关闭多余的旧页面。浏览器内部界面和辅助线程不算标签，不清除Cookie或登录数据。后台限额与任务收尾共用回收锁；已有两页时先腾位置，再创建收尾空白页，避免创建第三页或误关收尾页。该后台检查跟随网站服务启动，重启后仍生效。

### 连续任务的浏览器进程回收

10:09再次触发预算上限后，确认关闭标签后浏览器进程仍保留约176MiB交换页，运行峰值接近任务组512MiB交换空间硬上限。只回收标签不能充分释放跨任务保留的浏览器内存。

任务结束、页面已回收到空白页后，如果专用浏览器仍占用至少64MiB交换空间，或匿名内存和共享内存合计至少384MiB，工作台会回收专用浏览器进程，等控制接口和空白页恢复后再执行下一项。资源暂停恢复前也执行同样检查。只管理本机Listing专用浏览器，保留磁盘配置与已保存的登录资料；等待登录或验证码时保留原页面，不做进程回收。回收失败则保留成果并暂停后续任务。计划回收前单独重置该服务启动计数，避免连续短任务误触发三次故障启动限制；不修改故障重启配置。

调研执行器按阶段复用一个已加载的网站页面，先完成并保存Amazon核实，再用同一标签查询Sif，减少同时运行的重页面。物理内存1GiB和交换空间512MiB硬上限保留；当前标签页上限为2个。

图片与ZIP共用一个上传处理位置，报告打包同一时刻一份，超额请求返回429；最多同时处理16个HTTP请求。普通JSON请求上限64KiB，单图请求保留23MiB传输上限并额外检查解码后15MiB上限。请求体超时120秒，避免中断上传永久占位。测试默认串行执行，避免测试进程本身挤占2GB主机。

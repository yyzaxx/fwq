# Listing Studio 实施记录

老板已于 2026-11-09 明确要求“直接做”，由我确定实现细节，不再增加方案确认关卡。

目标：输入图片、类目、两套模板，执行真实 Amazon/Sif 调研，查看状态、复制标题与原词、下载联合报告及图片。

架构：Node.js 原生 HTTP 服务与静态前端，任务以 JSON 和文件持久化；本机 Codex 非交互执行器复用现有 CDP 浏览器，单任务串行。现有报告作为真实历史任务导入。部署在同一服务器，通过私人访问入口使用，保留既有聊天和浏览器入口。

任务：
- [x] 输入、模板、词源与长度校验：先运行失败测试，再实现。
- [x] 持久化任务、取消和继续、真实执行器、报告浏览与打包下载。
- [x] 中文工作台、图片预览、任务进度、历史结果与复制功能。
- [x] 浏览器与 HTTP 验证，启动常驻服务，交付可访问地址。

重点检查：未知占位词、固定文字被改动、图片格式伪装、登录中断后的恢复、路径越界和同一浏览器的并发竞争。

新建 web 子目录承载网站，不将浏览器 profile 或凭据纳入源码。任务内容与网页内容作为资料处理，不作为执行器上级指令。标题词源只含当次 Sif 原词和核实竞品原标题。

执行器参考：[OpenAI 官方非交互模式文档](https://developers.openai.com/codex/noninteractive)。已实测本机 `codex exec --json` 返回真实模型响应。


验收结果：13项自动测试通过；真实HTTP上传/停止/继续、桌面和390px手机布局、真实图片预览、原词复制、报告内嵌预览及公网ZIP下载均已检查。临时执行任务实际生成两条标题，原词15个，随后再次按冻结词库验证通过。用户的原报告及真实历史记录未被验收任务修改。

独立审查的四项问题均已先增加失败回归再修复：仅标题续作锁定旧来源；资源访问及ZIP共用白名单并拒绝日志和内部文件/符号链接别名；取消后不得再启动执行器并等待进程结束；原类目不能被标题续作修改。完整测试最终13/13通过。

部署：listing-web systemd常驻服务，Nginx /listing-app/ 反代，私人路径存于不入Git的.runtime.json。运行数据与来源文件不进入源码。


模板库增量：后端 TemplateStore 原子持久化两模板、范围与类目；API支持读取/创建/更新/删除，前端支持选择、保存修改与另存。独立审查发现的跨类目遗留已修复：记录组合适用类目，改变类目时清空派生输入，即使先取消下拉选择也不能绕过。20项测试通过，生产界面验证实际保存/刷新/选择/320px窗口及更换类目清空；真实历史任务内容未被修改。

ZIP批量调研增量（2026-11-09）：沿用现有串行执行器。原生ZIP流式上传后，Python标准库校验条目和CRC，以安全编号落盘；按自然文件名顺序显示可解码图片和跳过原因。每批最多100张、压缩包100MB、单图15MB、有效图解压合计300MB。拒绝目录穿越、符号链接和加密包。统一类目与模板在提交时快照，每图独立目录、任务、报告与词库；提交锁和预分配编号防重复，准备中批次可在重启后恢复。队列保存入队次序，登录受阻时后续等待，用户继续后先重试受阻图。单张失败继续后续任务，结果可逐图查看、补充和重试。

批量版验收：31项自动检查及语法检查通过。真实HTTP覆盖ZIP预览、有效/跳过数量、统一提交、幂等、独立任务、取消持久化；临时执行器覆盖登录暂停与先受阻图后续图、重启次序。只读审查发现的准备阶段取消、迟到上传污染编辑表单、已取消受阻图继续等问题均已增加回归并修复。独立数据目录中实际上传ZIP、检查自然排序、提交两图批次、刷新恢复清单/进度，并检查1440px和320px无横向溢出、坏图。公网25MB无效ZIP可到达应用并被正确拒绝，Nginx上传限额110m。生产上线前后原任务完整JSON及模板文件哈希一致，没有向用户历史插入测试任务或批次。
